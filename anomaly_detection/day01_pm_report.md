- (가) 실행한 출력 전체를 붙여 넣고, 읽기 성공한 줄과 읽기 실패한 줄이 각각 몇 줄인지, 읽기 실패한 줄이 어떤 줄인지 적어 주세요.

  - 답:성공: 28줄 실패:2줄 / 큰따옴표가 2개 미만인 줄 


- (나) 🔍 로그 한 줄만 보고 알 수 있는 것과 알 수 없는 것을 구분해 적어 주세요. 예를 들어 203.0.113.50 의 요청에서 접속자가 누구인지, 로그인에 성공했는지는 알 수 있나요?
  - 쓸 내용: ① 로그 한 줄만 보고 알 수 있는 것 ② 알 수 없는 것 ③ 203.0.113.50 의 요청으로 본 예
  - 답:알 수 있는 것 : 요청을 보낸 단말의 공인 ip주소, 접근 시각 및 요청방식, 호출한 url 자원 경로 , 서버 응답 상태코드

  - 쓸 내용: ① 한 번의 404 와 연달아 난 404 의 차이 ② 한 줄만 봐서는 판단하기 어려운 이유
  - 답:404 한번인경우: 일반 사용자가 오타를 내어 존재하지 않은 페이지를 클릭햇거나 삭제된 게시글 주소로 접속했을때 발생하는 단순 실수, 정상적인 웹 브라우징 에러입니다 / 404가 연달아 난 경우 : 공격자가 웹 취약점 스캐너를 구동하여 웹서버의 설정 파일, 관리자 로그인 페이지 데이터 베이스 관리도구 등 알려진 관리 인터페이스 경로를 무차별 탐색하는 공격 행위입니다 
  한줄만 봐서 판단하기 어려운 이유: 하나의 로그 줄만 보면 각각의 이벤트는 평범한 에러일수 있습니다. 그러기 때문에 여러 줄을 묶어어서 시간순으로 보았을때 동일 ip가 짧은시간 내에 민감한 관리자 경로들을 반복하여 요청한 패턴이 드러납니다 그래서 공격자로 의심을 하는 것 입니다 

## 6교시 · 이상 징후 가르기와 SIEM(심)

- (가) 실행한 출력 전체를 붙여 넣고, 분류별 요청 수와, 의심으로 분류한 요청 중 같은 주소에서 반복된 것을 적어 주세요.

- (나) 🔍 상태 코드와 경로만으로 분류를 정하면 놓치는 것이 있습니다. 샘플 로그에서 놓친 예를 두 가지 찾아(정상이나 오류로 분류됐지만 살펴볼 만한 요청) 왜 놓쳤는지 적어 주세요.
  - 쓸 내용: ① 놓친 예 두 가지 ② 각각 왜 놓쳤는지
  - 답:203.0.113.50이 POST /login 401을 5회 연속 실패한 뒤 바로 이어서 보낸 요청은 상태 코드가 200또는 302 이므로 코드가 단순 정상으로 분류 했습니다.한 줄 단위로만 검사하여 바로 직전의 5회 연속 실패 흐름을 알지 못해 무차별 대입 성공 의심건을 놓쳤습니다. / 98.51.100.90이 /.env, /wp-login.php, /phpmyadmin을 연달아 찔러 보았으나 서버에 해당 파일이 없어 404가 반환되었습니다 경로에 어드민이 없고 상태코드가 401/403이 아니라는 이유로 단순 시스템 오류로 분료 되었습니다 실제로는 해커가 자동화 도구로 관리자 페이지와 설정 파일을 탐색하는 공격 징후인데 한 줄씩만 보고 404 단순 페이지 없음으로 취급 하여 놓쳤습니다 

- (다) 🔍 5교시 「현업에서 SIEM(심)을 쓰는 방식 여섯 가지」 표의 방식 중에서, 보안 전담 직원이 1명뿐이고 쓰는 서비스 대부분이 클라우드에 있는 작은 회사라면 어느 방식을 고를지 이유와 함께 적어 주세요. 고르지 않은 방식 하나가 왜 맞지 않는지도 적어 주세요.
  - 쓸 내용: ① 고른 방식과 이유(로그 양 · 인력 · 데이터 위치) ② 고르지 않은 방식 하나와 맞지 않는 이유
  - 답:클라우드 방식, 관리형 / 이유는 서버 하드웨어를 직접 구매하거나 설치할 필요가 없어 빠르게 도입할 수 있고 회사 주요 서비스가 이미 클라우드에 있으므로 클라우드 서비스 로그를 api로 연동하기 가장 편합니다 보안 전담 인력이 1명뿐이고 하드웨어 유지보수나 os 패치에 시간을 뺏기지 않고 탐지된 이벤트 분석 및 대응에만 집중 할 수 있습니다 
  설치형 / 회사 내부에 로그 저장용 서버 장비를 직접 구매 구축해야 하므로 초기 도입 비용이 크고 전담 인력 1명이 장비 장애 대응, 디스크 용량 증설 os패치까지 도맡아 운영하기에는 인력과 리소스가 턱없이 부족 하기 때문입니다
