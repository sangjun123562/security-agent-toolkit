- (가) 실행한 출력 전체를 붙여 넣고, 경고 두 줄이 각각 어떤 오류 때문에 나왔는지 적어 주세요.
  - 쓸 내용: ① 출력 전체 ② 경고 두 줄이 각각 어떤 오류 때문에 나왔는지
  - 답:첫번째 경고 지정한 경로에 파일이 존재하지 않아서 생긴 경고
  두번째 경고 json문법 규칙상 마지막 항목 뒤에 불필요한 쉼표가 남아있어 파싱실패 경고 

```
config/users.json -> 사용자 6 명을 읽음, 판정을 계속한다
[경고] 설정 파일 없음: config/users_typo.json
config/users_typo.json -> 사용자 0 명, 등록된 사용자가 없다
[경고] 설정 파일 깨짐: config/users_broken.json
config/users_broken.json -> 사용자 0 명, 등록된 사용자가 없다
```

- (나) 🔍 실패했을 때 프로그램을 멈추지 않고 빈 설정을 리턴하는 것이, 오류로 멈추는 것보다 왜 안전한가요? 「멈춘 뒤 현장에서 생기는 일」을 넣어 적어 주세요.
  - 쓸 내용: ① 빈 설정을 리턴하는 이유 ② 멈춘 뒤 현장에서 생기는 일
  - 답:프로그램이 예외로 비정상 종료되면 정산포털 등 서비스 자체가 먹통이 되어 업무가 마비 된다 이 경우 현장 담당자가 문제를 빠르게 수습하려는 압박감에 판정 검사 로직을 통째로 꺼버리고 모든 요청을 무조건 통과시키는 열림 기본값 상태로 임시 조치할 위험이 크다 반면 빈 설정을 리턴하면 프로그램은 정상 실행을 유지하면서 모든 사용자를 등록되지 않은 사용자로 차단하는 닫힘 기본값 상태가 되므로 비인가 접근이나 정보 유출 같은 보안사고를 방지 할 수 있어서 훨씬 안전하다 

- (다) 🔍 설정 파일이 깨져서 모두 거부되면 정산 업무가 멈춥니다. 운영자가 이 상황을 빨리 알고 복구하려면 판정 프로그램에 무엇을 더하겠습니까? 두 가지 이상 적고, 그중 가장 먼저 할 것을 고른 이유를 적어 주세요.
  - 쓸 내용: ① 더할 것 두 가지 이상 ② 가장 먼저 할 것과 그 이유
  - 답:슬랙: 잔디 등 사내 메신저나 보안 관제 채널로 에러 로그와 경로를 즉시 발송하는 실시간 알림 웹훅 연동
  설정 파일 수정 시 문법 오류를 사전에 감지하여 정상적인 파일만 배포 되도록 막는 사전 문법 검증기 도입
  설정 파일 오류 발생시 직전의 정상 설정 파일을 즉시 읽어오는 자동 롤백/백업 캐시 참조 메커니즘 구축 
  실시간 알림 웹훅 연동을 가장 먼저 적용해야함 운영자가 장애 발생 사실 자체를 인지하지 못하면 원인 파악과 복구 조치가 지연되기 때문에 문제가 터지는 즉시 관리자에게 상황을 전달하여 골든타임을 확보하는 것이 최우선임
