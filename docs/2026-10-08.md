# 2026-10-08 아침 과제  학습 기록

## 1. Git 명령어 단계 분리 이유
- **질문**: git으로 올릴 때는 왜 `add` · `commit` · `push` 세 단계로 나눌까요?
- **정리**:
  - `add`: 수정한 여러 파일 중 이번 버전에 기록할 파일만 골라 담는(Staging) 단계입니다.
  - `commit`: 고른 파일들에 작업 설명(커밋 메시지)을 붙여 내 PC의 로컬 저장소에 하나의 기록 단위(스냅샷)로 저장하는 단계입니다.
  - `push`: 로컬에 완성된 커밋 기록들을 원격 저장소(GitHub)로 전송해 공유하는 단계입니다.
  - 세 단계로 나누면 작업 단위를 깔끔하게 쪼개서 관리할 수 있고, 불필요하거나 미완성된 파일이 실수로 원격에 올라가는 것을 방지할 수 있습니다.

## 2. 용어 정리
- **commit (커밋)**:
  - 파일의 특정 변경 시점 상태를 스냅샷으로 영구 기록하는 행위입니다.
  - 나중에 변경 이유를 추적하고 문제가 생겼을 때 특정 시점으로 복구할 수 있도록 작업 의도를 담은 커밋 메시지를 함께 작성합니다.
- **push (푸시)**:
  - 내 로컬 PC 저장소에 커밋해 둔 변경 이력들을 원격 저장소(GitHub)로 업로드하여 동기화하는 작업입니다.

## 3. 실습 진행 내용
- `git config`를 통해 사용자 이름과 이메일 등록 완료
- `git status`로 Untracked, Staged 상태 확인 및 보안 점검 (.env, .venv 차단 확인)
- `docs/2026-10-08.md` 작성 후 `git add` -> `git commit` -> `git push` 파이프라인 수행
