## 4교시 · 구역 규칙 코드

### 문제 4-1 · 규칙 판정 코드 읽고 설명하기

- (가) 함수 `default_policy` · `match_rule` · `judge` 가 각각 무엇을 하는지 적어 주세요.
  - 쓸 내용: 「default_policy: … / match_rule: … / judge: …」 함수마다 자유롭게
  - 답:default_policy: 규칙표에 일치하는 규칙이 없을때 적용되는 함수 match_rule: 하나의 규칙에 대해 요청의 출발 구역, 도착 구역, 포트 번호 3가지가 모두 일치하는지 검사하여 True 또는 False를 반환합니다 judge: 칙표를 1번 규칙부터 순서대로 훑으면서 가장 먼저 일치하는 규칙의 동작과 번호를 반환하고, 일치하는 규칙이 없으면 default_policy 결과와 번호 0을 반환합니다.
- (나) `judge` 가 리턴하는 값 두 개는 무엇이고, 어느 줄이 만드나요?
  - 쓸 내용: 「값 ①: … / 값 ②: … / 만드는 줄: …」
  - 답:리턴하는 값 두 개: 규칙의 동작(action, 예: "permit")과 규칙 번호(no, 예: 1)입니다. (맞는 규칙이 없을 때는 기본 정책의 동작과 0을 반환)

만드는 줄:

일치 규칙 리턴: return rule[4], rule[0] (19번 줄)

기본 정책 리턴: return default_policy(src, dst), 0 (20번 줄)
- (다) 🔍 `judge` 의 `for` 는 맞는 규칙을 찾으면 바로 `return` 합니다. 같은 요청에 규칙이 둘 이상 맞는다면 어느 규칙이 적용되나요? 왜 `return` 으로 바로 끝내도록 만들었나요?
  - 쓸 내용: ① 규칙이 둘 이상 맞을 때 적용되는 규칙 ② 방화벽이 「첫 번째로 맞는 규칙」을 쓴다는 점과 이어서 `return` 으로 바로 끝내는 이유
  - 답:규칙표에서 더 위쪽에 있는 '가장 먼저 일치한 규칙(First Match)'이 적용됩니다.

이유: 실제 방화벽의 핵심 동작 원리인 First Match(첫 번째 일치) 방식을 구현하기 위해서입니다. 방화벽은 위에서부터 순서대로 읽다가 일치하는 규칙 하나만 적용하고 아래 규칙은 보지 않아야 하므로, 일치하는 순간 바로 return하여 불필요한 탐색을 멈추고 결과를 확정 짓도록 만들었습니다.

### 문제 4-2 · 허용 포트 목록 함수 채우고 흐름 그리기

- (가) 채운 `allowed_ports` 함수를 붙여 넣고, 실행해서 나온 출력 네 줄을 적어 주세요.
  - 쓸 내용: ① 채운 함수 ② 출력 네 줄
  - 답:[443]
[445]
[22, 80, 443, 445, 3389]
[]

```
def allowed_ports(src, dst, ports):
    result = []
    for port in ports:
        action, no = judge(src, dst, port)
        if action == "permit":
            result.append(port)
    return result
```

- (나) `judge` 함수의 흐름을 ASCII 도식(상자 · 화살표)으로 그려 아래 코드 블록에 넣어 주세요.

  - 답:

```
START
         │
         ▼
    [ Take rule from RULES ] ◄────────────────┐
         │                                    │
         ▼                                    │
   / match_rule? \                            │ No (next rule)
  <  (src, dst,   > ─── No ──► [ Next rule? ] ┘

         │                            │ No (end of RULES)

```

- (다) 🔍 `allowed_ports` 에서 `result = []` 를 `for` 위에 두는 이유는 무엇인가요? `for` 안에 두면 어떻게 되나요?
