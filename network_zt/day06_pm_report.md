## 5교시 · 왜 도커인가 · 이미지와 컨테이너 · 같이 설치하기

### 문제 5-1 · 설치를 확인하고 첫 컨테이너 실행하기

- (가) `docker --version` 으로 나온 값을 적어 주세요.
  - 쓸 내용: 「Docker version … build …」 한 줄
  - 답:Docker version 29.8.2, build 7fc2dff
- (나) 🔍 `docker run hello-world` 출력이 말하는 일의 순서를 5.5 그림의 번호(① ~ ④)에 맞춰 설명해 주세요.
  - 쓸 내용: ① ~ ④ 번호마다 한 일 (클라이언트 · 엔진 · Docker Hub · 컨테이너)
  - 답:1. The Docker client contacted the Docker daemon.
 2. The Docker daemon pulled the "hello-world" image from the Docker Hub.
    (amd64)
 3. The Docker daemon created a new container from that image which runs the
    executable that produces the output you are currently reading.
 4. The Docker daemon streamed that output to the Docker client, which sent it
    to your terminal.
- (다) 🔍 `docker images` 에 보인 것과 `docker ps -a` 에 보인 것은 각각 이미지와 컨테이너 중 무엇이고, 어떻게 다른가요?
  - 쓸 내용: ① images 에 보인 것과 그 종류 ② ps -a 에 보인 것과 그 종류 ③ 둘의 차이
  - 답:IMAGE,Id,DISK USAGE,CONTENT SIZE,EXTRA/CONTAINER ID,IMAGE,COMMAND,CREATED,STATUS,          PORTS,NAMES
- (라) 🔍 `docker images` 출력을 붙여 넣고, `hello-world` 줄의 `IMAGE` · `ID` · `EXTRA` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `IMAGE` · `ID` · `EXTRA` 의 값과 뜻
  - 답:image: 이미지이름과 태그 최선버전을 의미/id: 해당이미지를 유일하게 식별할 수 있는 고유해시 id 값/extra: In Use의 약자로, 이 이미지를 사용해 만들어진 컨테이너가 로컬에 존재함(종료된 컨테이너 포함)을 나타냄.

```
IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
hello-world:latest   11a3eb1597e8       25.9kB         9.49kB    U  
```

- (마) 🔍 `docker ps -a` 출력을 붙여 넣고, `hello-world` 줄의 `STATUS` · `PORTS` · `NAMES` · `IMAGE` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `STATUS` · `PORTS` · `NAMES` · `IMAGE` 의 값과 뜻
  - 답:STATUS (Exited (0)): 컨테이너가 오류 없이 정상 코드(0)를 반환하고 실행을 마쳤다는 현재 상태.

PORTS (비어 있음): 호스트 PC와 컨테이너 내부를 연결하는 네트워크 포트 매핑이 없어 외부에서 접근할 수 없는 상태.

NAMES (festive_curie): 사용자가 이름을 지정하지 않아 도커 엔진이 무작위로 자동 부여한 컨테이너 고유 이름.

```
CONTAINER ID   IMAGE         COMMAND    CREATED         STATUS                     PORTS     NAMES
03d6d45d3e08   hello-world   "/hello"   5 minutes ago   Exited (0) 5 minutes ago             quizzical_panini
```

### 문제 7-1 · 컨테이너 안의 변경이 사라지는 것을 보고, 내 폴더를 연결하기

- (가) 컨테이너 안에서 바꾼 뒤 `docker rm -f web` 으로 지우고 다시 켰을 때 화면이 어떻게 되었는지 적어 주세요.
  - 쓸 내용: ① 바꾼 뒤 화면 ② 지우고 다시 켠 뒤 화면
  - 답:<h1>inside</h1>로 변경했을 때는 브라우저에 "inside"가 출력되었으나, 컨테이너를 삭제하고 다시 실행하자 변경했던 내용이 사라지고 초기 상태인 "Welcome to nginx!" 기본 안내 화면으로 되돌아갔습니다. 
- (나) 🔍 컨테이너 안에서 바꾼 내용이 사라진 이유와, `-v` 로 폴더를 연결하면 무엇이 달라지는지 적어 주세요.
  - 쓸 내용: ① 사라진 이유 ② -v 로 연결하면 달라지는 점
  - 답:사라진 이유: 컨테이너 내부 파일 변경 사항은 읽기 전용 이미지 레이어 위의 임시 쓰기 가능레이어에만 저장되고 컨테이너를 삭제 하면 컨테이너 레이어와 수정 내역이 함께 영구 삭제 되기 때문 /-v 연결시 달라지는점: pc의 로컬 디렉터리와 컨테이너 경로가 실시간으로 마운트 되므로 파일의 실제 저장이 내 pc에 이루어짐 따라서 컨테이너가 삭제되거나 재생성 되어도 호스트 파일은 안전하게 보존되며 컨테이너가 항상 호스트의 최신 파일을 읽어 서비스 할 수 있다 
- (다) 🔍 `MSYS_NO_PATHCONV=1` 없이 `-v` 를 실행했을 때 화면에 무엇이 나왔고 왜 그랬는지 적어 주세요.
  - 쓸 내용: ① 화면에 나온 것 ② 그렇게 된 이유
  - 답:화면 결과: site-one 화면이 나오지 않고 기본화면인 Welcome to nginx!가 표시되었다 원인은 윈도우의 깃 배시 환경이 posix형태의 컨테이너 내부경로를 윈도의 스타일 경로로 자동 변환하여 엉뚱한 위치에 마운트 했기 때문 환경 변수를 앞에 주어야 깃배시의 자동경로 변환이 비활성화 되어 올바른 리눅스 경로로 정상 마운트 됨  

### 문제 7-2 · 서버 두 대를 띄워 포트로 구분하고, 파일을 고쳐 바로 반영되는지 보기

- (가) 두 주소(`8080` · `8081`)에서 보이는 화면을 각각 적어 주세요.
  - 쓸 내용: 두 주소의 화면 문구
  - 답:"site-one / 첫 번째 서버입니다" (수정 후: "site-one / 첫 번째 서버 — 문구를 고쳤습니다"
- (나) 🔍 `docker ps` 의 PORTS 열에서 두 서버를 구분해 주는 것은 무엇인가요?
  - 쓸 내용: PORTS 열에서 서버를 구분하는 값
  - 답:호스트 PC 측의 외부 바인딩 포트 번호 (8080 vs 8081)입니다.컨테이너 내부 포트는 둘 다 80/tcp로 동일하지만, 호스트의 접속 진입 포트가 각각 0.0.0.0:8080과 0.0.0.0:8081로 다르게 매핑되어 서로 다른 컨테이너로 라우팅됩니다.
- (다) 🔍 `:ro` 는 무슨 뜻이고, 왜 읽기 전용으로 연결하나요?
  - 쓸 내용: ① :ro 의 뜻 ② 읽기 전용으로 연결하는 이유
  - 답:뜻: Read-Only(읽기 전용)의 약어로, 컨테이너가 마운트된 디렉터리의 파일을 읽을 수만 있고 수정·삭제할 수 없도록 권한을 제한하는 옵션입니다. 이유: 웹 서버 프로세스가 웹 셸, 악성코드 또는 침해 사고로 탈취당하더라도 호스트 PC의 소스 코드와 설정 파일이 위·변조되거나 삭제되는 2차 피해를 방어하기 위한 최소권한(Least Privilege) 보안 조치입니다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(두 서버를 어떻게 띄웠는지)
  - 답:호스트 디렉터리 볼륨 마운트(-v)와 읽기 전용(:ro) 옵션을 적용하여 컨테이너 재생성과 무관하게 안전한 웹 콘텐츠 영속성을 확보했으며, 호스트 포트 분기(8080/8081)를 통해 단일 호스트 상에서 다중 웹 서버 격리 구동을 성공적으로 구현했습니다.
