# 2과목 회고 (10/21(수))
## 잘 이해한 것
- **Zero Trust 아키텍처 원칙**: "아무것도 신뢰하지 않고 지속적으로 검증한다"는 개념 아래, 정책 판단 지점(PDP)과 정책 집행 지점(PEP)의 분리 구조와 기본 차단(Fail-Closed) 설정의 보안적 중요성을 명확히 이해했습니다.
- **도커 기반 보안 점검**: `-p` 포트 포워딩 바인딩에 따른 네트워크 노출 범위(0.0.0.0 vs 127.0.0.1)의 차이, 내부 포트 불일치로 인한 장애(000 응답) 식별, 그리고 `docker logs`를 통한 디렉터리 스캐닝 공격 정황 파악 방법을 직접 체득했습니다.
- **로그 상관 분석(Correlation Analysis)**: 개별 로그 한 줄만 보면 정상적인 '허용'처럼 보여도, 시간차(10분 이내)와 단말기 식별값(Device ID)을 엮어 분석함으로써 우회 접속 시도를 탐지하는 파이썬 로직을 구현할 수 있게 되었습니다. 
## 막힌 것
- **7일 차 정책 로그 점검 및 8일 차 파이썬 로그 처리**: 대량의 JSON Lines 형식 로그를 파이썬 딕셔너리로 변환한 후, 시간 문자열(`HH:MM`)을 '분' 단위 정수로 환산하여 사용자별 최근 상태(`last` 딕셔너리)와 비교하는 복합 조건문(`if`)을 작성할 때 튜플 인덱싱 및 들여쓰기 오류로 디버깅하는 데 다소 시간이 걸렸습니다.
- **이상 징후와 정상 행위의 경계 판단**: 미등록 기기 차단 직후 등록 기기로 통과된 사례(`seoyeon`)처럼 단일 로그만으로는 공격자의 계정 탈취인지 사용자의 단순 단말 교체 실수인지 즉시 확정하기 어려워, 가설 설정과 추가 입증 자료(자산 대장, 접속 IP, 본인 확인)를 도출하는 과정에서 많은 고민이 필요했습니다.
